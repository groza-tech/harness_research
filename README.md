# Асимметрия агентного харнесса как источник рыночной власти

Экспериментальный стенд к дизайн-документу исследования (специальность 5.2.2).

Два LLM-агента ведут двусторонние переговоры о цене контракта на поставку.
**Модель у обеих сторон одна и та же.** Различается только харнесс —
программная обвязка: память о контрагенте, доступ к рыночным данным,
механизм обязательства, верификационный гейт, планировщик, режим контекста.
Стенд измеряет, как эта разница конвертируется в захваченный излишек.

Годе и Сандер (1993) показали: институт может заменить интеллект. Здесь
проверяется обратная сторона той же монеты — **неравенство институтов
порождает неравенство исходов при равном интеллекте**.

## Быстрый старт

```bash
python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"
```

Смоук инфраструктуры без единого рубля на API — детерминированный
mock-провайдер вместо модели, 2100 сессий за пять секунд:

```bash
bash scripts/run_smoke.sh
```

То же напрямую, если нужен контроль над параметрами:

```bash
.venv/bin/harness-asymmetry run --config configs/smoke.yaml --experiment all --provider mock --output outputs/smoke --report reports/smoke
```

Смета боевого прогона (ни одного вызова LLM):

```bash
.venv/bin/harness-asymmetry plan --experiment all
```

Проверка ключа и живости провайдера до дорогого прогона:

```bash
.venv/bin/harness-asymmetry doctor --ping
```

Ночной прогон — пилот, скрининг компонентов и симметричная база подряд, с
`caffeinate`, чекпоинтами и отчётами после каждого этапа:

```bash
bash scripts/run_night.sh
```

Пилот на реальной модели (§4.4 — оценить дисперсию и пересчитать требуемое $n$):

```bash
cp .env.example .env  # и прописать OPENROUTER_API_KEY
.venv/bin/harness-asymmetry run --config configs/pilot.yaml --experiment pilot --output outputs/pilot --report reports/pilot
```

Повторный запуск той же команды **догоняет недостающее**: готовые сессии
читаются из чекпоинтов, API за них не платится повторно.

> Если после `pip install -e .` появляется `ModuleNotFoundError: No module
> named 'harness_asymmetry'` — на macOS случается, что `.pth`-файлу
> editable-установки проставляется флаг `hidden`, а `site.py` такие файлы
> намеренно пропускает. Лечится одной командой:
> `chflags nohidden .venv/lib/python3.11/site-packages/*.pth`

## Что получается на выходе

Каталог прогона (`outputs/<имя>/`) — машиночитаемое сырьё:

| Файл | Что внутри |
|---|---|
| `run_manifest.json` | Пиннинг всего: версии моделей, SHA-256 промптов, сиды, отпечаток пула сценариев, конфиг целиком, версии пакетов |
| `events.jsonl` | Полный лог харнесса: одно событие — одна строка JSON |
| `sessions/*.jsonl` | Транскрипты сессий, они же чекпоинты для resume |
| `sessions.csv` | Плоская таблица сессий с покомпонентными дамми — вход эконометрики |
| `turns.csv` | Ходы: токены, латентность, срабатывания гейтов, невалидные выводы |
| `run_meta.json` | Итоги прогона и здоровье провайдера |

Каталог отчётов (`reports/<имя>/`) — то, что читает человек:

| Файл | Читатель | Содержание |
|---|---|---|
| `RUN_REPORT.md` | вы сами, наутро после прогона | Здоров ли прогон: доля технических сбоев и невалидных выводов, сработавшие предохранители, токены, латентность, деньги, контроль контрбалансировки, пересчёт требуемого $n$ |
| `RESULTS.md` | научрук и соавторы | Разложение дисперсии, основная спецификация, ZI-U/ZI-C, скрининг компонентов, градиент асимметрии, курс обмена, рыночный уровень, оговорки |
| `LOG_DIGEST.md` | вы при отладке | События по типам, самые долгие вызовы, ошибки провайдера, предохранители, отклонения гейтов |
| `report.html` | отправить одним файлом | Самодостаточная страница: таблицы и графики вшиты как data-URI |
| `tables/*.csv`, `figures/*.png` | статья | Готовые к вставке артефакты |

Отчёты, собранные на mock-провайдере, несут баннер: там эффект харнесса
возникает по построению, и результатом исследования такой прогон не является.

### Шесть компонентов и их экономические имена

Требование §3.3 дизайн-дока: у каждого компонента обязана быть экономическая
категория, иначе получится инженерная статья с экономическими декорациями.

| Код | Компонент | Экономическая категория |
|---|---|---|
| H1 | Память о контрагенте | Репутационный механизм; односторонний переход разовой игры в повторяющуюся |
| H2 | Рыночный ретрив | Снижение неопределённости о резервной цене контрагента |
| H3 | Механизм обязательства | Commitment device; стратегическое связывание рук (Шеллинг) |
| H4 | Верификационный гейт | Бюджетное ограничение в духе ZI-C (Годе–Сандер); мониторинг агента принципалом |
| H5 | Планировщик уступок | Способность к последовательной рациональности |
| H6 | Полный лог vs компакция | Издержки обработки информации; ограниченная рациональность как параметр |

`full_log = 0` означает **компакцию**, а не отсутствие контекста: «голая»
конфигурация должна быть дешёвой во всех смыслах. H6 — кандидат на компонент
с отрицательной отдачей: экономия на токенах покупается уступкой излишка.

## Модели и параметры вызова

Слаги запиннены в `.env` и попадают в манифест прогона:

| Класс | Слаг | Цена (вход/выход, $/M) |
|---|---|---|
| light | `qwen/qwen3.7-flash` | 0.030 / 0.130 |
| mid (рабочая лошадка) | `deepseek/deepseek-v4-flash-0731` | 0.080 / 0.180 |
| heavy | `xiaomi/mimo-v2.5-pro` | 0.435 / 0.870 |

Одномодельные эксперименты (пилот, Э2, Э5) идут на `HA_MODEL`; разброс весовых
классов нужен только там, где он предмет измерения — в Э1 и Э4.

**Токены модели не режем.** `HA_MAX_TOKENS` и `HA_REASONING` по умолчанию
пусты — параметры не отправляются вовсе, модель работает в штатном режиме, как
в реальном контуре. Это не только про чистоту эксперимента: у рассуждающей
модели тесный `max_tokens` съедается мыслями, и ответ приходит **пустым** с
`finish_reason=length` — выглядит как сбой провайдера, будучи ошибкой
конфигурации. От разгона защищает бюджет токенов на сессию
(`runner.max_tokens_per_session`) — предохранитель в харнессе, который считает
по факту, а не догадка о том, сколько модели «должно хватить».

Пустой ответ клиент считает **неудачной попыткой** и уходит в backoff (6 попыток,
до 45 с) — flash-модели под нагрузкой регулярно отдают HTTP 200 с пустым
`content`. Пустые ответы в кеш не кладутся: закешированная пустота молча
отключила бы весь механизм повторов. Счётчик `empty_responses` — в отчёте.

## Инженерные решения и почему они такие

Дизайн-док §7.1 запрещает тяжёлый фреймворк: нужна полная наблюдаемость и
возможность точечно отключать компоненты. Здесь свой минимальный цикл, и
каждое решение отвечает конкретному требованию.

**Компоненты отключаются независимо.** Единственная точка ветвления по битам
— `harness/assembler.py`. Тест `test_every_vector_assembles` прогоняет все 64
конфигурации и проверяет, что множество активных компонентов совпадает с
множеством единиц вектора. Если компонент нельзя отключить, не сломав другой,
план эксперимента неисполним.

**Память изолирована по сторонам.** У каждой стороны свой `MemoryStore`;
чтение чужого владельца бросает `MemoryIsolationError`, а не возвращает
пустой список. Тихая пустота означала бы, что баг проходит незамеченным и
обнуляет половину плана. Проверяется `tests/test_memory_isolation.py`.

**Язык и действие разделены.** Цена извлекается парсером из поля JSON, а не
регуляркой из текста. Невалидный вывод — до трёх повторов, затем сессия
помечается техническим сбоем и исключается; доля сбоев публикуется в
`RUN_REPORT.md`, а не заметается под ковёр.

**Пиннинг всего.** Версии моделей, SHA-256 каждого шаблона промпта, сиды,
отпечаток пула сценариев, конфиг целиком и версии пакетов уходят в
`run_manifest.json`. Правка формулировки промпта меняет хеш — рецензент
видит, что прогон был на другом промпте.

**Общие случайные числа.** Пул $(v,c)$ строится один раз и раздаётся всем
ячейкам по индексу повтора; I0 и I1 видят идентичные розыгрыши. Это парный
дизайн — разница между «эффект значим» и «эффект в шуме».

**Контрбалансировка встроена в план.** Каждые четыре повтора дают полный цикл
роль × очередь хода. В литературе зафиксирована ролевая асимметрия
LLM-агентов; без контрбалансировки мы измерили бы её вместо своего эффекта.

**Наблюдаемость — JSONL, одно событие на строку.** Отладка сводится к
`grep session_id | jq`, а не к внешнему вендору обсервабилити. В событии есть
`trace_id`/`span_id`/`parent_span_id` в духе OTel GenAI, учёт токенов,
`latency_ms` и `stop_reason`. Промпты и ответы в лог не пишутся — только их
SHA-256 и длина.

**Предохранители живут в коде, а не в промпте.** Лимиты раундов, токенов и
времени модель не может «уговорить» себя обойти. Отдельно — детектор
залипания: отпечаток хода включает предложение контрагента, чтобы отличить
агента, который держится за свою цену, пока контрагент уступает (стратегия),
от агента, у которого вообще ничего не меняется (зависание).

**Залипание не обрывает сессию** (по умолчанию). Протокол и так ограничен
$2T$ ходами, а досрочный обрыв подменял бы честное «сделки не было»
техническим сбоем и смещал бы выборку против компонентов, чья суть — стоять
на своём. Сигнал при этом сохраняется: событие `harness.stuck`, поле
`stuck_turns`, строка в отчёте. Кому важнее экономия — `abort_on_stuck: true`.

**Чекпоинты с первой строки.** Каждая завершённая сессия немедленно
дописывается в `sessions/<ячейка>.jsonl` с `flush`. Прогон на 200 тыс.
вызовов упадёт посередине — resume подхватывает готовое.

**Параллелизация — по ячейкам, не по сессиям.** Внутри ячейки сессии идут
строго последовательно: память (H1) накапливает историю пары от повтора к
повтору, и перестановка повторов сломала бы репутационный механизм.

### Два решения, которые стенд принимает за вас (и почему)

**Несостоявшаяся сделка не имеет доли.** $\phi^A$ считается только по
состоявшимся сделкам; провал торга учитывается метрикой $D$ и нулевой $E$.
Записать 0 или 0,5 вместо отсутствующего наблюдения — подмена данных, из-за
которой компонент, чаще срывающий сделки, выглядел бы скромным переговорщиком.

**Запрещённый приём становится отказом, а не сделкой по другой цене.** Когда
гейт не пропускает `accept`, подставить свою цену нельзя: контрагент такой
цены не предлагал, и «сделка» возникла бы из воздуха — иногда за пределами
резервных величин обеих сторон. Единственный корректный исход — отказ в этом
раунде. В этом и состоит цена связанных рук: механизм обязательства может
стоить сделки, и это его экономическое содержание, а не дефект.

## Планы экспериментов

| План | Что варьируется | Гипотеза | Команда |
|---|---|---|---|
| `pilot` | Две крайние ячейки | оценка дисперсии, пересчёт $n$ | `--experiment pilot` |
| `E1` | Симметричная лестница 0→6, три класса моделей | H5 (насыщение) | `--experiment E1` |
| `E2` | Плакетт–Бёрман на 6 компонентах, B голая | H2 (какой компонент главный) | `--experiment E2` |
| `E3` | Выжившие компоненты × уровни асимметрии × I0/I1 | H1 (градиент ренты) | `--experiment E3 --survivors memory verifier market` |
| `E4` | (модель × уровень) по обеим сторонам | H3 (курс обмена) | `--experiment E4` |
| `E5` | Популяция, разброс обвязок при неизменном среднем | H4a/H4b | `--experiment E5 --agents 24 --periods 8` |

`plan` печатает смету по каждому: ячейки, сессии, вызовы LLM, порядок токенов.

## Порядок работы

1. `harness-asymmetry doctor --ping` — конфиг, ключ, провайдер живы.
2. Смоук на mock: `--config configs/smoke.yaml --experiment all --provider mock`.
   Убедиться, что все четыре отчёта собираются и таблицы не пустые.
3. **Пилот** на реальной модели (§4.4). Открыть `RUN_REPORT.md`, раздел
   «Пилот и мощность»: там пересчитанное требуемое $n$ по фактической
   дисперсии. Это точка невозврата — если $n$ непосилен, менять сеттинг
   (упрощать сценарии, снижать $T$), а не гнать основной прогон в надежде.
4. Э1 и Э2 → отобрать выживших. Список выживших печатается в `RESULTS.md`.
5. Э3 с этими выжившими, Э4, Э5.
6. `harness-asymmetry report` пересобирает отчёты из готового прогона
   сколько угодно раз, не трогая API.

Проверка чувствительности к формулировке (§6.4) — прогнать один и тот же план
с `--prompt-variant base|terse|formal` в разные каталоги; эффект обязан
сохраняться на всех трёх.

## Тесты

```bash
.venv/bin/python -m pytest -q
```

Покрывают чек-лист §7.3 и всё, что дорого чинить постфактум: изоляция памяти,
связывающее обязательство, бюджетное ограничение верификатора, совпадение
учёта протокола с аналитикой Рубинштейна, отсутствие утечки приватной
информации в режиме I1, общие случайные числа, ортогональность плана
Плакетта–Бёрмана, чекпоинты и resume, сборка всех отчётов.

## Источники по инженерии харнессов

Инженерная часть опирается на практику harness engineering, а не только на
дизайн-док:

- [Awesome Harness Engineering](https://github.com/ai-boost/awesome-harness-engineering) — паттерны, память, разрешения, наблюдаемость, оркестрация
- [Observability in Agent Harnesses](https://rahulkashyap.dev/blog/harness-observability.html) — схема JSONL-события, `stop_reason`, предохранители, детекторы залипания
- [JSONL as the Native Observability Format for AI Agent Runtimes](https://zylos.ai/research/2026-06-06-jsonl-agent-observability-data-format/) — одно событие на строку, один файл на сессию
- [Agent Harness Engineering (O'Reilly Radar)](https://www.oreilly.com/radar/agent-harness-engineering/) — внутренний и внешний харнесс, компакция контекста
- [Why LLM Evaluation Results Aren't Reproducible](https://www.promptlayer.com/blog/why-llm-evaluation-results-arent-reproducible/) — пиннинг модели, температуры, сида и хешей промптов
- [Reproducible LLM Benchmarks: What Everyone Forgets to Pin](https://aisecbench.com/posts/reproducible-llm-scanner-benchmarks/) — манифест прогона и чекпоинты по ячейкам

Научная рамка — дизайн-документ исследования: Годе–Сандер (JPE 1993),
Рубинштейн (Econometrica 1982), Майерсон–Сатертуэйт (JET 1983), Шеллинг
(1960), Кальвано и др. (AER 2020).
